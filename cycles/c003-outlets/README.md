# サイクル3: 出口の数（刻みで進める計算のずれ）

1 つの槽から出口が何本か出ているとき、刻み dt で進める計算の「残り」は、厳密な答えからどれだけ外れるか。
出典は [FluidFullSpeedSimulation](https://github.com/myon-bioinformatics/FluidFullSpeedSimulation) の E29 🚿 `outlet-count`。
野球（[サイクル1](../c001-chunichi/README.md)）とも米価（[サイクル2](../c002-gohantrust/README.md)）とも違い、**答えが式で分かっている**題材。
説明を命題にして、どこで成り立たなくなるかを判例で見る手順は同じ（[docs/propositions.md](../../docs/propositions.md)）。

## 進め方

1. 命題を書いて固定する（第1弾 [`propositions.toml`](propositions.toml) はコミット b126b0d、第2弾 [`propositions_r2.toml`](propositions_r2.toml) は 4851a04、第3弾 [`propositions_r3.toml`](propositions_r3.toml) は 8ab22a9、第4弾 [`propositions_r4.toml`](propositions_r4.toml) は 3ce4460、第5弾 [`propositions_r5.toml`](propositions_r5.toml) は 991cd01、第6弾 [`propositions_r6.toml`](propositions_r6.toml) は 61815c7、第7弾 [`propositions_r7.toml`](propositions_r7.toml) は 09ec9e7。どれもその回の単位を作る前（第4弾はエンジンへの実装より前）。ハッシュは [`prelock_stamp.txt`](prelock_stamp.txt)）
2. 単位を作る（FluidFullSpeedSimulation のエンジンで計算。[`units.jsonl`](units.jsonl) 2890 単位 = 第1弾 338 + 第2弾 140 + 第3弾 460 + 第4弾 450 + 第5弾 308 + 第6弾 704 + 第7弾 490、出どころは [`units_provenance.json`](units_provenance.json)）
3. 別実装で検算する（エンジンを使わない float の漸化式。2890 単位すべてで err の差は最大 4.7e-12）
4. PythDRagoras で 4 つの形を判定し、判例を並べる（[`outputs/objections.md`](outputs/objections.md)、一覧は [`outputs/index.md`](outputs/index.md)）
5. 結果を見て出た着想は「未検討」に置くだけで、その場では走らせない

```bash
python cycles/c003-outlets/outlet_units.py make --ffs <FluidFullSpeedSimulation の場所>   # 単位を作り直す
python cycles/c003-outlets/outlet_units.py check                                          # 検算（エンジン不要）
uv run python cycles/c003-outlets/outlet_judge.py --report-only                           # 判定して outputs/ に書く
```

## 単位と方式

単位 = 1 回の計算。槽の最初の量 128、合計の時定数 τ = 32、測る時刻 t ≈ 2τ（ステップ数は round(2/h)）。

| 組 | 中身 | 単位の数 |
|---|---|---|
| 弁だけ | 1・2・3・4・8・16 本 × 等分／偏り × 刻み 10 通り × 方式 2 つ | 220 |
| 弁 + ポンプ | 弁 1・2・4 本 + ポンプ 1 本（q = 最初の量·K/8）× 刻み 10 通り × 方式 3 つ | 90 |
| ポンプだけ | 1・2・4・8 本 × 刻み 2 通り × 足りる／途中で足りなくなる | 16 |
| 弁 + 遅れの管 | 1・2・4 本 × 刻み 2 通り × 方式 2 つ（遅れ τ/4） | 12 |
| 第2弾 `gentle` | 弁 1・2・4 本 + 弱いポンプ（q = 最初の量·K/64）を t ≈ τ/2 で測る × 刻み 10 通り × 方式 3 つ。厳密な残りは最初の量の 6 割ほど | 90 |
| 第2弾 `chain` | 槽 A（弁 1 本、τ）→ 槽 B（弁 1 本、τ2）→ 受け。τ2/τ = 1/4・1/2・3/4・2・4 × 刻み 10 通り。t ≈ 2τ の槽 B の量を Bateman の式と比べる | 50 |
| 第3弾 `native` | エンジンの既定（`outlets="exact"`）で、弁だけ 2・3・4・8・16 本（等分／偏り）、第1弾 mixed・第2弾 gentle と同じ条件の弁 + ポンプ × 刻み 10 通り | 160 |

| 第3弾 `fed` | ポンプ（一定の速さ）→ 槽（弁 1 本、τ2/τ = 1/4・1・4）→ 受け × 刻み 10 通り × 方式 2 つ（independent・uniform）。t ≈ 2τ | 60 |
| 第4弾 `flow` | 第3弾の fed・chain2 と同じ条件を、エンジン本体の `inflows="uniform"` で進める | 110 |
| 第4弾 `combo` | 入るポンプ（V0·K/4）+ 弁 1・2・4 本（等分／偏り）+ 出るポンプ（V0·K/8）× 刻み 10 通り × 入る量の扱い 2 つ（end・uniform） | 100 |
| 第4弾 `chain3` | 3 段の槽。(τ2/τ, τ3/τ) = (1/2, 1/3)・(2, 1/2)・(1/3, 3)・(3, 5) × 刻み 10 通り × 入る量の扱い 2 つ | 80 |
| 第4弾 `ring` | 2 つの槽の輪。τ2/τ = 1/4・1/2・2・4、測る時刻 2T（行き渡る途中）・40T（行き渡った後）× 刻み 10 通り × 入る量の扱い 2 つ | 160 |
| 第5弾 `chain3b` | 3 段の槽。(τ2/τ, τ3/τ) = (1/4, 3/4)・(3/4, 1/4)・(3/2, 4)・(4, 3/2)・(2/5, 5/2)・(6, 1/5)、t ≈ τ・3τ × 刻み 11 通り（1/256 を足した）× 入る量の扱い 2 つ | 264 |
| 第5弾 `chain4` | 4 段の槽。(τ2/τ, τ3/τ, τ4/τ) = (1/2, 1/3, 1/4)・(2, 1/2, 3)・(1/3, 3, 1/2)・(3, 5, 2)、t ≈ 2τ × 刻み 11 通り。end だけ | 44 |
| 第6弾 `edge3` | 3 段の槽。end のずれが 0 を横切る 3 組 (3/2, 4)・(4, 3/2)・(2/5, 5/2) を、横切る時刻の 0.8〜1.2 倍の 8 通りで測る。横切らない 2 組 (1/4, 3/4)・(6, 1/5) は t ≈ τ・2τ・3τ。刻み 11 通り × 入る量の扱い 2 つ | 660 |
| 第6弾 `edge2` | 2 段の槽。τ2/τ = 1/5・3/5・5/4・5、t ≈ 1.5τ、刻み 11 通り。uniform だけ | 44 |
| 第7弾 `cross3` | 3 段の槽。end のずれが 0 を横切る 5 組 (5, 2)・(3/10, 2)・(3, 5/4)・(1/2, 3)・(3/5, 5/2)。刻み 1/256〜1/8 の 7 通り。式で 0 を横切るステップ n0 の −2〜+2 と 0.7·n0・1.3·n0 で測る × 入る量の扱い 2 つ。同じ計算は 1 つだけ | 490 |

刻み h = dt/τ は 1/128・1/64・1/32・1/16・1/8・1/4・1/2 と、2 の累乗でない 3 つ（0.0478・0.343・0.74。A×10^-N を種 3 で引いた）。

| 方式 | 取り方 |
|---|---|
| `independent` | 今のエンジン。弁はどれもステップ最初の量の 1 − e^(−k·dt) を取る |
| `joint` | 同じ槽の弁をまとめ、合計で 1 − e^(−K·dt) を取ってから速さの比で分ける |
| `affine` | ポンプも含めて dV/dt = −K·V − q を 1 ステップぶん厳密に解く。ポンプは q·dt、残り (V + q/K)(1 − e^(−K·dt)) − q·dt を弁へ分ける |

| `uniform`（第3弾） | 入ってくる量 I が 1 ステップのあいだ一定の速さで入ると見なす。出る量 = B·(1 − e^(−x)) + I·(1 − (1 − e^(−x))/x)、x = dt/τ2 |
| `through`（第3弾） | 2 段を 1 ステップぶん厳密に解く。槽 B の新しい量 = B·e^(−k2·dt) + A·k1/(k2 − k1)·(e^(−k1·dt) − e^(−k2·dt)) |

`joint` と `affine` は、単位を作るスクリプトがエンジンの登録口（`register_law`）に法則を足して計算している。`affine` と同じ取り方は、その後エンジンの既定（`outlets="exact"`）として入った（FluidFullSpeedSimulation #16。第3弾の `native` で確かめ直した）。
第3弾の `uniform` と `through` は、スクリプトがエンジンと同じ固定小数点（Q48、床）の整数で漸化式を進めている（エンジンは出る量をステップ最初の量までに抑えるので、法則を足すだけでは入らない）。
第4弾では `uniform` をエンジン本体に入れた（`Network(inflows="uniform")`。その後 FluidFullSpeedSimulation #17 で既定になった）。入れ方: まず今までどおり全部の管の量を決め、次に槽ごとに「このステップに届く量 I」を使って弁の合計を V·Φ + (I − P)·(1 − Φ/L) まで増やす（増やす分は I まで。増やした分は下の槽の I に数えない）。

## 列

| 列 | 意味 |
|---|---|
| `team`・`season`・`team_name` | 単位の名前（PythDRagoras の決まり）。`team` = 組、`season` = 組の中の刻みの通し番号 |
| `n`・`h`・`equal_split` | 出口の本数（弁がある槽は弁の本数）・刻み dt/τ・等分かどうか |
| `valve_only`・`mixed`・`pump_only`・`has_delay`・`gentle`・`chain` | 組（どれか 1 つが真。`valve_only` は遅れのない弁だけ） |
| `independent`・`joint`・`affine` | 方式（どれか 1 つが真） |
| `err`・`err_abs` | 計算の残り / 厳密な残り − 1 と、その大きさ（厳密な残りが 0 のときは差そのもの） |
| `err_pred`・`fo_rel` | 1 次の式 −t·dt·(K² − Σk_i²)/2 と、\|err − err_pred\| / \|err_pred\| |
| `ceil_ratio` | \|err\| / (t·dt·K²/2)。頭打ちに対する割合 |
| `drop_from_fewer` | err − 同じ刻みで 1 つ少ない本数の err |
| `halving_ratio`・`has_half` | err / 同じ組で刻みが半分の単位の err と、その単位があるか |
| `corr_gain` | \|err\| / \|1 次の式で直した後の err\| |
| `src_same`・`lag_err_steps` | 遅れのない同じ組と槽の残りが 1 ulp も違わないか・届くまでのステップ数のずれ |
| `starved`・`conservation_q` | ポンプが途中で足りなくなるか・総量のずれ（ulp） |
| `euler_ratio` | \|err\| / \|(1 − K·dt)^N / e^(−K·t) − 1\|。出口を無限に細かく分けたときの形に対する割合 |
| `so_rel` | 2 次の式 exp(−t·dt·(K² − S2)/2 − t·dt²·(K³/3 − K·S2/2 + S3/6)) − 1 との相対差（S2 = Σk_i²、S3 = Σk_i³） |
| `disc_gap` | 離散の閉じた式 (1 − Σ(1 − e^(−k_i·dt)))^N / e^(−K·t) − 1 との差 |
| `joint_ratio` | joint の err / 同じ本数・刻みの independent の err |
| `first_err_abs`・`chain_halving`・`tau2_ratio` | chain の 1 段目の \|err\|・刻みが半分の単位との err の比・τ2/τ |
| `native`・`chain2`・`fed`・`uniform`・`through` | 第3弾の組と方式 |
| `chain_pred_rel` | \|err − dt/(2·τ2)\| / (dt/(2·τ2))（chain2 の independent） |
| `fed_gap` | \|err − (x/(1 − e^(−x)) − 1)\|、x = dt/τ2（fed の independent） |
| `gain_vs_independent` | \|同じ条件の independent の err\| / \|この単位の err\|（uniform） |
| `uniform_halving`・`span_ratio` | uniform の err / 刻みが半分の単位の err・測る時刻 / τ（ring は / T） |
| `flow`・`combo`・`chain3`・`ring`・`uniform_in`・`from_pump`・`settled` | 第4弾の組、エンジンの `inflows="uniform"` で進めたか、flow の上がポンプか、ring を行き渡った後に測ったか |
| `native_gap` | \|err − 第3弾の同じ条件の uniform（整数の漸化式）の err\|（flow） |
| `chain3_pred_rel`・`tau3_ratio` | \|err − (dt/(2·τ2) + dt/(2·τ3))\| / (dt/(2·τ2) + dt/(2·τ3))（chain3 の end）・τ3/τ |
| `chain3b`・`chain4`・`stage_fit`・`sign_ok`・`tau4_ratio` | 第5弾の組、\|err − G_eff の式の予想\| / ((dt/2)·Σ_{i≥2} k_i)、err と予想の向きが同じか、τ4/τ |
| `edge3`・`edge2`・`uni_fit`・`uni_fit2` | 第6弾の組、\|err − G_eff(uniform) の式の予想\| / ((dt·k_max)²/12)、\|err − k1·k2·dt²/12\| / (k1·k2·dt²/12) |
| `cross3`・`end2_fit`・`pred_margin` | 第7弾の組、\|err − G_eff(end) の 2 次までの式の予想\| / ((dt·k_max)²/12)、\|uniform の式の予想\| / \|end の式の予想\| |
| `h_star`・`h_ratio` | 式から出した境目 \|a1/b2\|/τ（end の 1 次の係数 / uniform の 2 次の係数）と、h / h_star |
| `gain_vs_end`・`flow_halving` | \|同じ条件の end の err\| / \|この単位の err\|・err / 刻みが半分の単位の err（エンジンの uniform） |

コード 4 が多いのは判定規則どおり: 判例が 1 つも無い「必ず」の命題は、対偶（B でないなら A でない）に当たる単位が 0 件になり、対偶は判断保留になる。

### 判例が教えること

- **O3（34 件）**: 1 次の式が 5 % を外すのは h ≥ 0.25 の単位だけ。外れ方は刻みにほぼ比例する（最大で h = 1/8 が 3.3 %、1/4 が 6.7 %、1/2 が 14 %、0.74 が 19 %）
- **O4 の逆（36 件）**: 5 % 以内なのに h > 1/32 の単位。h = 0.0478〜0.125 は全部、h = 0.25 と 0.74 は一部が 5 % 以内。境の 1/32 は安全側に寄りすぎていた（境は動かさない。記録だけ）
- **O5（2 件）**: 16 本・h = 1/2 で頭打ちを 1.8 %（等分）と 1.3 %（偏り）超えた。頭打ちは 1 次の見積もりで、粗い刻みと多い本数では高次の項で超える。h = 1/2 以外では最大 0.989
- **O7 の逆（34 件）**: 比が 1.9〜2.1 に入るのは h = 1/4 まで（2.04〜2.07）。h = 1/2 は 2.08〜2.14 で一部が外れる
- **O8 の逆（30 件）**: 直した後のずれは h = 1/8 まで 1/10 以下（11.6〜15.4 倍）。倍率はほぼ 1.5/h で、直した残りは刻みの 2 次。h ≥ 0.25 では 5.4 倍以下
- **O10（27 件）**: 弁をまとめてもポンプが混ざるとずれる。2 本・h = 1/128 で independent −3.0 %、joint −1.6 %（半分にはなるが消えない）。h ≥ 0.343 では厳密な答えより先に空になる（err = −1）。成立した 3 件は h = 0.74 で、厳密な答えも空（0）の単位
  - この組は厳密な残りが最初の量の 2.7 % しかないので、同じ量のずれでも割合では大きく出る

### 判例が教えること（第2弾）

- **O16**: 置き直した上限は 1 件も超えない（最大 0.96）。O5 の判例 2 件は、上限を 1 次で見積もったことが原因だった
- **O17（8 件）**: 判例は全部 h = 1/8 で 3 本以上（0.51〜0.70 %。2 本は 0.41 % で収まる）。逆・裏は判例 0 件で、0.5 % 以内に収まった単位はどれも h ≤ 1/8。外れ方は刻みの 2 乗にほぼ比例（h = 1/16 で 0.18 %、1/32 で 0.045 %）

- **O23（50 件）**: 槽が 2 段つながると、出口が 1 本ずつでも 2 段目は必ずずれる。向きは多い側で、大きさは dt/(2·τ2) ほど（h = 1/128 で τ2/τ = 1/4 が +1.6 %、1/2 が +0.78 %、2 が +0.20 %、4 が +0.098 %）。出口の数によるずれ（同じ刻みで 16 本 −0.73 %）より大きいこともある

- 弁の開き具合が水位で変わる槽（線形でない出口）、細管・樋などが出口の槽に入る量

## 既知の欠け

- 境の値（1e-9・5 %・h ≤ 1/32・10 倍・1.9〜2.1）は人が決めた仮置きで、結果に合わせて動かしていない
- O1・O2・O6 と O4・O7 の細かい刻みの側は、E29 の数字を知ったうえで書いた追試（`propositions.toml` の冒頭に記録）
- 単位を作った後、判定の前に、検算が 3 件の食い違いを止めた（弁 + ポンプ・affine・h = 0.74）。原因は厳密な答えの側の誤りで、槽が空になった後を 0 で止めていなかった。厳密な答えと検算の漸化式を 0 で止めるよう直して作り直した。命題の結果を見る前の訂正
- 単位の名前は PythDRagoras の `team`・`season`・`team_name` に合わせている（野球の列名のまま）
- エンジンは FluidFullSpeedSimulation の main 2a02cf3（既定が `outlets="exact"`・`inflows="uniform"` になった後）。第4弾の判定は、まだ `inflows` の既定が end だったブランチの a3231a1 で作った単位で行い、その後 main で作り直して 1388 単位の値が 1 つも変わらないことを確かめた。第1弾〜第3弾の組は `inflows="end"` を指定して作る。第1弾・第2弾の組は `outlets="independent"` を指定して作るので、作り直しても 478 単位の値は 1 つも変わらない（bcea72f・5c5e1dc で作った値と同じ）
- 第3弾の判定を見た後の訂正が 1 つある。最初の判定で O15（総量）に判例が 30 件出た。原因は単位を作るスクリプトの数え方の誤りで、fed・uniform の漸化式が、使わない槽 A の最初の量を総量に数えていた（ずれはどれもちょうど −128）。数え方を直して作り直した。変わったのはその 30 単位の `conservation_q` と `first_left` だけで、err と他の命題の結果は変わらない
- 検算（素の漸化式）が比べるのは err だけで、総量の列は比べていない。上の誤りが検算をすり抜けたのはそのため
- 第4弾の検算は、エンジンの入れ方（先に全部の量を決め、後から弁を増やす）を float で書き直したもの。エンジンと同じ考え方の別実装で、式そのものの正しさは厳密な解との比べ（err）が担う
- O41 は当たる単位が 8 件で、判定の決まり（10 件）に足りなかった。命題を書くときに数えていなかった。第5弾の O47 で、別の 36 件で問い直した
- 第5弾の式は、導いた後・命題を書く前に、第4弾の単位 1 件（(τ2/τ, τ3/τ) = (1/3, 3)・h = 1/128）と照らしている（式 +0.122 %、単位 +0.122 %）。判定に使った単位は別の組
- 第6弾は、単位の組を決めるために式だけを使って計算している（0 を横切る時刻と、その前後の境目）。データは使っていない。粗い刻みで測る時刻が丸まり、同じ計算が複数の単位として入った（edge3 の uniform 330 件中、別々の計算は 261 件）。命題を書くときに見落としていた
- 第7弾も、単位の組を決めるために式だけを使って計算している（end の式が 0 を横切るステップと、その前後の比）。第6弾の反省から、同じ計算は 1 つだけ作り、粗い刻みは使っていない。そのぶん、確かめた範囲は h ≤ 1/8 に限られる
- `stage_fit` の式の予想は、G_eff で進めた量を行列の指数関数（スクリプトの中の小さな実装。Bateman の式と 1e-13 で一致）で出している。README の 3 段の式とは 1 % 以内で同じ（テストで確かめている）
- 第2弾の命題は第1弾の id を `parent` に持つ。PythDRagoras は `parent` を同じファイルの前の方に求めるので、判定のときは 2 つのファイルを順につないで 1 つとして読んでいる（ファイルそのものは変えない）
- O17・O18 の式は紙の上で導いたものだが、境（0.5 %・h ≤ 1/8）は第1弾の外れ方（刻みにほぼ比例）を見た後に置いた
