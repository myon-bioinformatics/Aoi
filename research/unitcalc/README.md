# unitcalc: 単位付き計算（第2弾の道具）

任意の単位で計算し、次元の違反を止め、丸めで消えた分（余り・誤差 δ）を厳密な値のまま出す。標準ライブラリのみ・実装は 1 ファイル。

主な使い方は**係数探し**: 気体定数 `R_gas`・アボガドロ定数 `N_A` のような係数を、別の単位系（L·atm、cal、Torr…）で書き直したり、測定値から作った係数の次元と値が既知の定数と噛み合うかを見たりする。為替・株価は扱わない。

ここでいう「単位」は計測単位（m、J、W、円、個…）で、`docs/data-policy.md` の観測単位（チームなど）とは別のもの。結論は書かない。道具の仕様と確かめたことだけを書く。

| ファイル | 役割 |
|---|---|
| [`unitcalc.py`](unitcalc.py) | 実装（次元・量・単位表・構文・表示・CLI）。標準ライブラリのみ |
| [`benchmark.py`](benchmark.py) | 速さの目安。生サンプルを JSON で出す |
| `tests/test_unitcalc.py` | 契約と反例（144 件） |

```bash
python research/unitcalc/unitcalc.py "3 kW * 2 h -> kWh"      # 式は引用符で囲む
python research/unitcalc/unitcalc.py --steps "sqrt(2 m^2) -> m"  # 近似の途中式つき
printf '1 kWh -> J\n7 h // 2 h\n' | python research/unitcalc/unitcalc.py   # 式が無ければ 1 行 1 式
python research/unitcalc/unitcalc.py "R_gas -> L*atm/(mol*K)"   # 気体定数を別の単位系で
python research/unitcalc/unitcalc.py "1 kWh = 3.6e6 J"           # 左辺 = 右辺: 両辺の次元と値の確認
python research/unitcalc/unitcalc.py --dim JPY --dim item -D 'pack=12 item' '2 pack -> item'
python -m pytest tests/test_unitcalc.py -q
```

```text
$ unitcalc "R_gas -> L*atm/(mol*K)"
≈ 0.0820573660809596 L*atm/(mol*K)
δ +3412/4053×10⁻¹⁶  (≈8.42×10⁻¹⁷) L*atm/(mol*K)
🧭 kg·m²·s⁻²·K⁻¹·mol⁻¹ ✅
$ unitcalc "10 J / 3 s -> W"
≈ 3.33333333333333 W
δ +1/3×10⁻¹⁴  (≈3.34×10⁻¹⁵) W          ← 真の値 − 表示 = 厳密に (1/3)×10⁻¹⁴
🧭 kg·m²·s⁻³ ✅
$ unitcalc "6 kWh -> W"
❌ 🧭 出力の次元が合わない: 結果 kg·m²·s⁻² ≠ 単位 kg·m²·s⁻³        (終了コード 65)
```

オプション: `--digits N`（表示の有効桁、既定 15）、`--bits N`（根の有効ビット、既定 64）、`--steps`（途中式）、`--json`（1 式 1 行）、`--dim NAME`（基本次元を足す）、`-D NAME=式`（単位を足す）。

## 量と計算の規則

量は 中心 `m` ± 半径 `r`（どちらも厳密な有理数 `Fraction`）と次元からなる。`r = 0` が厳密な値。

| 操作 | 規則 |
|---|---|
| `+` `-` | 次元が同じものだけ。違えば 65（`🧭 m ≠ s`）。半径は足す |
| `左辺 = 右辺` | 次元が違えば 65。一致すれば、両辺とも無次元かを知らせ、値が等しいか（厳密 / 異なる / 範囲が重なって判定できない）と、異なるときの差（厳密）を出す |
| `*` `/` | 厳密。次元は積・商。半径は `|a|·rb + |b|·ra + ra·rb`。0 を含む範囲では割らない |
| `//` `%` | 厳密な量だけ（近似値は切り捨ての境が決まらず拒否）。`a % b = a − (a // b)·b`。次元は `//` が a/b、`%` が a のまま（b が単価 `円/個` でもよい） |
| `^` | 指数は厳密な無次元の数。`^(p/q)` は根。次元の指数が整数にならなければ拒否（`√m`）。完全冪（`√(4 m²)`）は厳密 |
| 根 | 完全冪でなければ **誤差球**（真の値を必ず含む `m ± r`）。`⌊x·2^(q·k)⌋` の整数 q 乗根（`math.isqrt` / 整数 Newton）で下限・上限を取り、途中式を量に残す |
| `-> 単位` | 次元が一致するときだけ換算。一致しなければ 65 |
| float | 受け付けない（`0.1 m + 0.2 m` はちょうど `0.3 m`） |

構文の注意: 数と単位は一体で、`1/3 m` は 1 ÷ (3 m)。`(1/3) m` と書く（無次元の括弧・関数の直後なら単位を続けられる）。`10 m / 2 s` は `10 m` ÷ `2 s`、`3 m/s` は 3 (m/s)（演算子の次が単位名のときだけ単位の連なりが続く）。`J/kg*K` は左から順に (J/kg)·K。`2^3^2` は拒否（括弧で書く）。`×` `·` `÷` `−` `→` と上付き指数（`m²` `s⁻¹`）も読める。

## δ（余りと誤差）の出し方

近似が入るのは「根」と「有限桁での表示」だけで、どちらも黙って丸めない。

- **表示で落とした分**: 値を有効桁 `sig` で 0 方向へ切り捨て、`値 = (q + frac)×10^-s`、表示 = `q×10^-s`、**δ = frac×10^-s**（`frac` は余りの分数）。`--steps` で `(10/3)×10^14 = 333333333333333 + 1/3` の形の途中式が出る。`frac = 0` なら `=`、そうでなければ `≈` と δ の行。JSON の `mid` が厳密な値、`shown + delta = mid` がテストで厳密に成り立つ。
- **根**: 誤差球の `mid ± rad` を厳密な分数で保持し、表示は誤差半径で保証できる桁までに切って `δ ∈ [下限, 上限]` を出す（A×10^-N の形で、外向きに丸めた 3 桁）。後続の計算（掛け算・割り算・引き算）にも球のまま伝わり、`√2 − √2` は 0 と言い切らず `0 ± 2r` になる。
- **ゼロ**: 0 での割り算（0 を含む範囲での割り算も）は止めて 65 を返す。ε への置き換えはしない（置き方は別に決める。docs の方針どおり黙って埋めない）。NaN・∞ は有理数に存在しない。

## ビットに倒した所・倒さなかった所

- **次元**（倒した）: 8bit × 32 スロットを 1 つの `int` に詰め、指数 −32..31 を `e+32` で持つ。積 = `((a+b) | GUARD) − BIAS`、商 = `((a | GUARD) − b) + BIAS`。ガードビットでスロット間の桁上がり・借りを防ぎ、`& RANGE` 1 回で全スロットの範囲外（上溢れ・下溢れ）を検出する。一致判定は `int` の比較。テストは乱数のスロット単位の計算と全一致を確かめる（`test_dim_swar_matches_per_slot_arithmetic`）。
- **根・桁**（倒した）: ずらし幅はビット長から決め、`x·2^k` はシフト、10 の桁の見当は `bit_length` から（`_e10`）。
- **有理数の足し引き・掛け算**（倒さなかった）: `Fraction` に任せた。倍率がほぼ 2 の冪・10 の冪の単位でも、約分の `gcd` を自前で置き換える利得より、読みやすさと厳密さを取った。

## 定数と係数探し

SI 2019 の**定義値**から厳密に決まる定数を単位表に持つ（誤差のある測定値の定数 G、m_e、M_u などは入れていない。±σ は厳密な包含ではなく、同じ誤差球に載せると意味が変わるため）。

| 名前 | 値 |
|---|---|
| `c_0` `h_P` `k_B` `N_A` `q_e` | 299792458 m/s、6.62607015e-34 J·s、1.380649e-23 J/K、6.02214076e23 mol⁻¹、1.602176634e-19 C（すべて定義値） |
| `R_gas` `F_Far` | `N_A·k_B` = 8.31446261815324 J/(mol·K)、`N_A·q_e` = 96485.3321233100184 C/mol（定義値の積なので厳密） |
| `g_n` `T_0` | 9.80665 m/s²、273.15 K（0 °C の定義。温度の値で、差ではない） |

SI 以外の単位は表に厳密な定義値があるものを入れた（`L` `atm` `bar` `Torr` `mmHg` `cal` `eV` `Wh` `min` `h` `d` `t` `in` `ft` `yd` `mi` `lb` `pct` `ppm`）。足りなければ `-D 'furlong=201.168 m'` で足す。例:

```bash
unitcalc "R_gas -> cal/(mol*K)"                       # 1.98720425864083 cal/(mol*K)
unitcalc "R_gas * T_0 / 1 atm -> L/mol"               # 標準モル体積 22.4139695450141 L/mol（δ つき）
unitcalc "(101325 Pa * 22.414 L) / (1 mol * 273.15 K) / R_gas"   # 測定値の係数 ÷ R。🧭 無次元 なら噛み合っている（≈1.0000014）
unitcalc "(101325 Pa * 22.414 L) / R_gas"             # 無次元にならない（🧭 K·mol が残る）= 係数として合っていない
```

係数 `k`（`PV = k·nT` の `k` など）は `k = 左辺 / 右辺` で作る。次元は自動で出るので、既知の定数と同じ次元か、比が無次元かで見分けられる。値の比較は厳密な分数で行い、測定値の丸めは差として残る。

## 次元の知らせ（無次元・左辺 = 右辺）

- 結果に単位がなければ、`🧭 無次元 ✅（単位なし）` と明示する（JSON は `dimensionless: true`）。出力の単位を指定しなくても、一致する名前付きの単位（J、W …）か SI 基本単位の形で次元を出す。
- `左辺 = 右辺` は両辺の次元を並べ、一致すれば ✅、違えば 65。**両辺とも無次元**ならそう知らせる（`7 h // 2 h = 3` など）。片方だけ無次元なら次元違反。値は厳密に等しいか、異なるか（差を厳密に出す）、誤差球が重なって**判定できないか**を分けて返し、判定できないものを「等しい」とは言わない。

## SI 以外・個数・金額（買い物の例。為替は扱わない）

SI の単位も、後から足す単位も同じ仕組み（`Reg`）。`--dim` で基本次元を足し、`-D` で単位を足す。金額と個数は別の次元なので足せず、`//` と `%` で「何個買えるか・あまりいくらか」を厳密に出せる。

```bash
unitcalc --dim JPY --dim item "1000 JPY // 300 JPY/item"   # 3 item（買える個数）
unitcalc --dim JPY --dim item "1000 JPY % 300 JPY/item"    # 100 JPY（あまり）
```

割引は率（無次元）と値（金額）を**次元で区別する**。率を値として引く・値を率として掛けるのは 65 で止まる。

| やりたいこと | 式（`--dim JPY`） |
|---|---|
| 率で引く | `1000 JPY * (1 - 20 pct)` → 800 JPY |
| 値で引く | `1000 JPY - 300 JPY` → 700 JPY |
| 値 → 率 | `300 JPY / 1000 JPY -> pct` → 30 pct |
| 率 → 値 | `1000 JPY * 30 pct` → 300 JPY |
| 支払ったあとの割引値 | `1000 JPY - 700 JPY` → 300 JPY（率は上の「値 → 率」） |
| 個数と率 | `3 * 298 JPY * (1 - 10 pct)` → 804.6 JPY（厳密） |

通貨ごとの次元・レート・株価は入れない。`kg` や `mm` のように接頭辞つきで読める名前は、`--dim` / `-D` で上書きできない。`shrink-index`（総量 = 枚数 × 1枚の重さ）や `bigmac-ruler`（kg あたり、換算なし）への採用は別の変更で、この変更は既存コードを触らない。

## 実測

2026-11-07、Linux x86_64・CPython 3.13.18。各時間はウォームアップ後 7 回の中央値（1 回あたり）。生サンプルは `python research/unitcalc/benchmark.py` が JSON で出す。

| 項目 | 中央値 |
|---|---:|
| 次元の積（ビット詰め `d_mul`） | 0.19 µs |
| 次元の積（スロットごとに取り出して足して詰め直す素直な書き方） | 8.9 µs |
| 量 + 量 / 量 * 量 / 量 / 量（厳密、次元つき） | 約 1.0 µs |
| √2（64 ビットの誤差球） | 16 µs |
| `3 kW * 2 h -> kWh`（構文・計算・表示まで） | 53 µs |
| `10 J / 3 s -> W`（余りの δ つき） | 64 µs |

小規模な測定で、機械の負荷や実行順序で変わる。一般的な速さを示すものではなく、閾値も置かない。次元の積は素直な書き方の約 50 倍だが、全体の時間は量の `Fraction` 演算と表示が占める。この規模では Rust を足す理由は測れていない（足す場合の入口は、熱い所の `Q` の演算と `_cut` を 2〜3 ファイルの拡張に置き換える形で、別の変更として測ってから決める）。

## 保証範囲・できないこと

- 厳密なのは + − × ÷ // % と整数・有理数の冪まで。√ などは誤差球（`--bits` で精度を変える）。`exp`・`log`・三角関数は未実装（無次元の引数が前提になる）。
- `Hz` と `s⁻¹`、`rad`・`sr` と無次元は同じ次元（区別しない）。`J` と `N·m` も同じ。
- 原点がずれる単位（`degC` `degF`）は拒否する（倍率だけでは換算できない）。差は `K` で書く。
- 単位の倍率は定義値が厳密なものだけ（SI 接頭辞と上の一覧。`cal` は熱化学カロリー、`mmHg` は 13595.1 kg/m³ × g_n × 1 mm の慣習値）。年・月・ガロンなど定義が複数あるものは入れていない（`-D` で足せる）。
- 比較演算子（`<` `>`）は未実装。誤差球どうしの比較は、重なるときに「判定できない」を返す設計が必要で、別の変更にする。
- 次元スロットは 32（SI 7 + 追加 25）。指数は −32..31。超えると 65。
- 検証した環境: Linux・CPython 3.11 と 3.13（`tests/test_unitcalc.py` 144 件）。他の版・OS は未確認。

## 終了コード

`docs/propositions.md` の 64 以上（システム側の失敗）に合わせる。判定側は数を比べ、表示の文字列を比べない。

| コード | 意味 |
|---|---|
| 0 | 計算できた（δ や誤差球が出ていても 0。値は JSON の `exact` / `delta` / `rad` で区別する） |
| 65 | 入力の誤り（構文・未知の単位・次元違反・0 での割り算・厳密でない定義など）。標準入力の複数式では、誤りの式があっても残りを計算し、最後に 65 を返す |
| 66 | 式がない |
| 70 | 内部の不変条件が破れた |

## 継続時の入口

`unitcalc.py` が実装、`tests/test_unitcalc.py` が契約と反例、`benchmark.py` が測定。依存を足さずに再開できる。次は、不確かさつきの測定値の定数（G、m_e など。厳密な包含とは別の意味づけが要る）、誤差球どうしの大小比較、`shrink-index` / `bigmac-ruler` での採用を、それぞれ別の変更として検討する。
