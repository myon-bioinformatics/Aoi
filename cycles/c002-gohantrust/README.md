# サイクル2: GohanTrust（米価と指標の組み合わせ）

青いプロジェクト第2弾。複数の指標を一つの式に組み込み、小さな標本で厳しい規律のもとに「ある項や形が米価を予測するか」を確かめる。サイクル1（[中日ドラゴンズ](../c001-chunichi/README.md)）と同じく、結論を急がず、判断できないものは判断できないと記録する。

## 練習式

GohanTrust は架空の練習式。実データで検証する手順を作るために置いている。

```text
P = K · q · (100 − A) · E
```

- P: 米の価格（円）。q = 5 kg（5kg あたりの価格として扱う）
- A: 青木率（内閣支持率 + 与党第一党支持率）
- E: エンゲル係数
- K: 係数（P から逆算する）

形の候補は `primary` (100−A)、`alt200` (200−A)、`exp_neg` exp(−βA)、`aoff` (A を使わない P ∝ q·E)、`prop_A`（符号を逆にした形）。A ≥ 100 では `primary` が成り立たない（2013年の年平均 A = 100.87）。

| 比較対象 | ゼロ変化、訓練期間の平均変化（ドリフト） | 同上 |

| 多重性 | 同じ主張に向けた検定の総数 m を数え、p_adj = min(1, m·p) を併記する | 各事前宣言 |

言い方の規則: 差が検出できないときは「判断保留（検出できず）」と書き、「効かない」「通らなかった」とは書かない。政治に関する因果の物語は書かず、定義だけを注に置く。

## 進め方

1. 事前宣言を書いて固定する（時刻とハッシュを記録）
2. 再現ゲート: 既知の結果を同じ手順で再現できるか確かめる。合わなければ本番を走らせない
3. 実行し、別実装で検算する
4. 報告を書く。結果を見て出た着想は「未検討」に置くだけで、その場では走らせない

## 既知の欠け

- 公表刻み 1 つ分（0.1 ポイント）は、年次の E では底だった（L1r）が、月次の E では底になっていない。月次の E の前年比はふつうの月でも刻みの約 4 倍動く。家計調査の標本のばらつきはまだ見積もっていない（[monthly/ §4](monthly/report_monthly_2026-11-13.md)）

- L1 の入力の P（米価）と E（エンゲル係数）は、Grok の報告書に載った値を転記したもの（2016〜2022年の P は整数丸め）。L1r は同じ量を、リポジトリ内の一次資料のパネル（`research/staple-price-survey/phase2_archive/`）から作り直した
- 転記値は `research/staple-price-survey/` の日本の系列と照合した（`tests/test_c002_lag1.py`）。**一致した範囲**: E の 2005〜2025年は家計調査（二人以上の世帯。2005〜2023年は e-Stat、2024〜2025年は統計局の年平均結果の概要で、つなぎ目の扱いは `research/staple-price-survey/staple_survey_readme.md` の Seam）、P の 2005〜2015年は小売物価統計調査の 5kg 月次（e-Stat）の年平均
- **P の 2016〜2025年も照合できた（2026-11-13、L1r）**: `research/staple-price-survey/phase2_archive/japan_retail_price_rice_panel.csv.gz` の銘柄 1002 都市平均の月次平均と、差は最大 0.030 %。2015年と2016年のあいだで系列は切り替わっていない。同じ表にある FPMA の東京 5kg 系列は別の系列（P はその 0.81〜0.93 倍の水準）
- E の公表値は 0.1 ポイント刻みで、ΔlogE にすると約 0.0034〜0.0043 の底がある。L1 の 2018・2019 の ΔlogE = 0 はこの刻みが作ったゼロだった。L1r は食料 ÷ 消費支出の実額を使う（[lag1/ §7.4](lag1/report_lag1_2026-10-24.md)）
- 青木率 A を含む形（`primary` など）の結果と、窓の延長（2005年以降）の結果も Grok の報告書によるもので、原本はこのリポジトリにない。L1 は A を使わない
- 国際比較のデータは [`research/staple-price-survey/`](../../research/staple-price-survey/)（データのみ）にある。L1 の入力の照合にだけ使い、検証には使っていない
- L1 の順列検定は、事前宣言 §7.2 の文面（窓内の全年をシャッフル）どおりだと、lag=1 の統計が読まない最終年（2025）を帰無に混ぜていた。2026-10-25 に、統計が読む年だけをシャッフルする版を主にして結果を作り直した（宣言どおりの版も並記。宣言ファイルは変更していない）。p は最大 0.02 動いただけで、読み方は変わらない。結果を見たあとの訂正である点も含め、[報告書 §6](lag1/report_lag1_2026-10-24.md) に残した。次の事前宣言では、順列で動かす年を「統計が読む年」と書くのがよい
