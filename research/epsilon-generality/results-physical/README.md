# ε の汎用性の確認（第 2 回）: 物理量の結果（探索）

事前登録は [../README.md](../README.md) の「物理量の確認（第 2 回）: 事前登録」（コミット e55721a）。スクリプトは `eps_generality.py`・`fetch_physical.py`（e55721a の版）と `posthoc_scale_tolerance.py`（2332224 の版。予想を走らせる前に書いて push した）。**登録した基準・入力・設定は結果を見て変えていません。** ε の値は暫定で、結論には使いません。

入力は登録した sha256 のとおりでした（月次 `4f18c60d…`、日次 `1d1ea18b…`。[physical_manifest.json](physical_manifest.json)）。なお `monthly/`・`daily/` の `eps_generality.md` 冒頭の「[README.md](../README.md)」は、このファイルを指します（基準は上の階層の README.md）。

## 要点

- 登録した基準 C1〜C3 は、**月次で 24 件、日次で 24 件のすべてを満たしました**。判定不能はなし、対照（C4）も通りました。「矛盾する材料はなかった」までしか言えません（見たのは大気・気候の測定だけです）
- 第 1 回（主食価格）で外れた 1 件（ほぼ同点の周期が ε=1e-3 のときだけ入れ替わり、係数のずれが 0.577）のような大きなずれは出ませんでした。係数のずれの最大は 0.9% 以下です
- 「減衰 0」が選ばれる単位（境界の単位）の割合は、月次 0.21〜0.38、日次 0.25〜0.40（野球は 0.14、主食価格は 0.36〜0.39）。野球より ε が効く場面が多い向きは、物理量でも同じでした。物理量では窓が 48 点だと割合が下がりました（主食価格では下がりませんでした）
- **報告だけにした「値の単位を変えたとき」で、物理量らしい問題が見つかりました。** 値の幅を 5 にそろえた尺度から小さくしていくと、月次は倍率 1e-6、日次は 1e-5 から、選ばれる式が動きました（倍率 1e-6 で月次 221 窓のうち 115、日次 478 単位のうち 272。日次は窓 480 個から値の幅が 0 の 2 個を除いた数）。事後の確認では、`EPS_WAVE_TIE`（絶対値の許容）に倍率の2乗をかけると、**どの倍率でも 0 件**になりました。この入力では、動きの原因は ε ではなく、この許容の絶対値でした

## 値の単位を変えたとき（登録した報告。基準はない）

値の幅を 5 にそろえたあとの y と τ に同じ倍率をかけて、24 点の窓を当てはめ直した（倍率 1 が基準）。

| 集合 | 倍率 | 境界の単位 | 式が変わった | 境界かどうかが変わった | 係数のずれの最大（相対） |
|---|---|---|---|---|---|
| 月次（221 窓） | 1e-6 | 47 | **115** | 38 | 6.4×10^-16（47 単位） |
| 月次 | 1e-3 / 1 / 1e3 / 1e6 | 85 | 0 | 0 | 1.3×10^-15 以下 |
| 日次（478 単位） | 1e-6 | 74 | **272** | 106 | **0.436**（70 単位）。「始まりの時点で決まっていた」かどうかが変わった単位 1 |

倍率 1e-3 以上では何も動かず、係数のずれは浮動小数点の誤差の範囲でした。動いたのは 1e-6 だけです。

## 事後の確認: 動きの理由（登録した基準の外）

走らせる前に書いた予想（[posthoc_scale_tolerance.py](../posthoc_scale_tolerance.py) の冒頭）は、(a) 許容をそのままにして倍率を細かく動かすと、動き始める倍率が見つかる、(b) 許容に倍率の2乗をかけると、どの倍率でも式は変わらない、でした。結果は [posthoc_scale_tolerance.md](posthoc_scale_tolerance.md)。**(a)(b) とも予想のとおりでした。**

式が変わった単位の数（24 点の窓。許容 `EPS_WAVE_TIE` = 1e-12 のまま / 許容に倍率の2乗をかけたとき）:

| 倍率 | 月次（221 単位）そのまま | 月次 2乗をかけた | 日次（478 単位）そのまま | 日次 2乗をかけた |
|---|---|---|---|---|
| 1e-8 | 207 | 0 | 470 | 0 |
| 1e-7 | 207 | 0 | 470 | 0 |
| 1e-6 | 115 | 0 | 272 | 0 |
| 1e-5 | 0 | 0 | 7 | 0 |
| 1e-4 / 1e-3 / 1e-2 / 1 | 0 | 0 | 0 | 0 |

- 倍率 1e-7 以下では、そのままだと境界の単位が 0 になる（ほぼ全部が「簡単な式のまま」に倒れる）。許容に倍率の2乗をかけると、どの倍率でも境界の単位の数・式・係数が倍率 1 と同じ（係数のずれは 6.4×10^-16〜5.8×10^-15）
- 読み方: この入力では、倍率による動きの**全部**が `EPS_WAVE_TIE` の絶対値で説明できた。`EPS_WAVE_SOLVE` は格子だけで決まり y によらないので、仮説の外
- 倍率は「値の幅を 5 にそろえた尺度に対する倍率」で、窓の値の幅（最大 − 最小）は 5×倍率。動かなかったのは、月次で幅が 5×10^-5 以上（倍率 1e-5 以上）、日次で 5×10^-4 以上（倍率 1e-4 以上）。格子は 10 倍刻みなので、動き始める境目はこの間にある。窓の点数（24）や雑音の大きさで変わる
- 例（概算。この単位では走らせていない）: CO2 を ppm ではなく mol/mol で扱うと、24 か月の窓の幅は数〜10 ppm、つまり 5×10^-6〜10^-5 くらいで、倍率にすると 1e-6〜2e-6 前後。この入力の 1e-6 の行（月次で 221 窓のうち 115 が動いた）に近い。幅が小さい単位（ひずみ、µV、濃度の分率など）を、値を正規化せずにこのコードへ渡すと、同じ動きが出うる
- **直し方は決めていません**（許容を値の尺度に対して相対にする、当てはめの前に値の幅をそろえる、など）。`sakanalytics` は変更していません（PR #24 は触っていません）。このハーネスは値の幅を 5 にそろえているので、C1〜C3 の結果は影響を受けていません

## 野球に寄っていた点・領域によらない点（第 1 回からの更新）

領域によらなかったもの（主食価格と物理量の月次・日次、いずれも）:

- 減衰 0 を ε に差し替える方法そのもの（C1）。係数が ε によらないこと（C2、ε が小さい範囲で。ε=1e-3 でも 0.9% 以下）。境界でない単位の結果を動かさないこと（C3）
- 「ε が効く単位の割合」は野球（約 14%）より高い（物理量で 0.21〜0.40）。野球の割合を ε の影響の大きさの目安にすると少なく見積もる

物理量で新しく見えたもの:

- **ε は x の単位に結びつくが、y の単位に結びつく別の絶対値（許容）がある。** x は窓の長さで [0, 1] にそろえてあるので ε は窓の長さに対する値として単位に依らない（そろえ方による）が、`EPS_WAVE_TIE` のような y 方向の絶対値は、値の尺度が 5 前後から 5×10^-5 前後より小さくなると効き方が変わる。野球の順位（幅 5）では目立たなかった
- x の単位を変えて試してはいない（このハーネスは窓の長さで正規化してから当てはめる）

## 限界

- 物理量といっても、大気・気候の測定（気温、CO2 濃度、風、降水）だけ。固体・電気・天体・生体の測定は入っていない
- 窓の数は独立な標本の数ではない。全球気温偏差の GCAG と GISTEMP、CO2 と季節調整後の CO2、2 地点・最高と最低の気温は互いに関連する。日次の窓は 12〜48 日で、季節（約 365 日）より短い
- 単位（mm、degC、m/s、ppm）は想定で、確かめていない。GCAG と GISTEMP の上流も確かめていない
- 境界の割合が高いことの理由、変数ごと（降水量は風や気温と同じか）の違い、周期の中身は調べていない（`eps_generality_units_n24.jsonl` には変数ごとの行がある）
- 値の単位の報告と事後の確認は y の倍率だけ。倍率は 10 倍刻みで、動き始める境目は決まっていない。理由は「この許容がこの入力での全部」までで、他の入力・他の長さの窓で同じかは見ていない
- 基準値は野球と第 1 回の値を目安にした。物理量のために置き直していない
