# R28: P96の取りこぼし54件からの合成データ限定探索

記録: 2026-10-15。PR #39の既存命題・必須合格条件は変更しない。実測の命題台帳にも加えない。
候補は別台帳 `outputs/synthetic_p96_candidates.json` の **SYN96-C01〜C06** として管理する。
成立率＝TP/(TP+FP)、説明範囲＝TP/(TP+FN)。正例は合成順位の下位半分であり、公式CS出場ラベルではない。

## 54件を二つの型に分ける

| 型 | 件数 | rd | 期待勝利数との差 | sim_p_upper | alloc_z_strat | P96から外れる箇所 |
|---|---:|---:|---:|---:|---:|---|
| 得失点は良いが勝利数が期待未満 | 26 | +72 | −16.26〜−15.26 | 0.585〜0.841 | −4.923〜−3.050 | rd<−50でなく、見込み<0.5でなく、rd<+50でもない |

前者はP96の「配分が不利」という分岐にrd<50という上限があるため逃す。後者は、期待値を上回ることとリーグ上位に入ることが同義でない例。
このreversed族の上位84件は全てrd=−30、残差+6.47〜+7.47であり、生成器が作った階層が非常に強い。閾値探索はこの構造を容易に拾う。

## 別IDの候補と探索手順

全候補は **P96の前件 OR 下記の追加条件 ⇒ 下位**。既存P96の定義を上書きしない。

| ID | 追加条件 |
|---|---|
| SYN96-C01 | P52の前件 |
| SYN96-C02 | alloc_z_strat < −1（rdの上限なし） |
| SYN96-C03 | wins_vs_pythag < 0（確率条件なし） |
| SYN96-C04 | rd ≥ 0 かつ wins_vs_pythag < 0 |
| SYN96-C05 | alloc_z_strat < 0 |
| SYN96-C06 | wins_vs_pythag < +5（グリッド選択） |

探索に使うラベルはbatch seed 0のreversed 168件だけ。C01〜C05は前件の緩和比較、C06は408通りの1〜2指標の追加条件から、追加FP=0、FN救済最多、条件数最少、辞書順の順で選択した。
グリッドはrd {−50,0,50}、残差 {−10,−5,0,5,10}、確率 {0.2,0.4,0.5,0.6,0.8}、配分 {−2,−1,0}の<と≥。同じ指標同士の積は除いた。
これは事前登録した閾値の検証ではない。28件の正残差を確認してから+5/+10を探索グリッドへ含めた、データ依存の探索である。
候補JSONをSHA `a1307c449e15bc92fa55b3174418f52fc5db08e87065901da790afb745ddd6d4` で固定してから、未使用のbatch seed 1・2を計算した。
追加の仮定変更はbatch seed 3、conversion=0.5とし、候補は再選択していない。得点規模は元の3.822333916083916のまま。

## 反例と残る問い

反例は各JSONの`metrics.*.ids.fp`、取りこぼしは`ids.fn`。全2016合成球団年の特徴量・全候補の前件真偽は `outputs/synthetic_p96_units.jsonl` に保存した。実測件数の増分は0。

| 種類 | 単位 | rd | 残差 | 確率 | 配分z |
|---|---|---:|---:|---:|---:|
| C02の追加分の転移反例 | b0/aligned/2013/P5 | 72 | -0.258 | 0.982 | -1.369 |
| C06の仮定変更反例 | b3/reversed/2013/C2 | -30 | 4.948 | 0.341 | 1.412 |
| C02でなお逃す下位 | b1/reversed/2013/C5 | -12 | 2.865 | 0.630 | 0.159 |

次に検討する問いは、①得失点差が良いのに不利な配分となる例を、他条件の上位と区別する追加観測は何か、②期待超過でも下位になる例を、期待勝利数の絶対残差でなくリーグ内の相対位置で説明できるか、の二つ。
どちらも新しい観測・別の生成族または未使用の実測年で確かめる必要がある。今回のprofile依存の閾値を現実の因果説明へ移さない。
実勝利数を含む残差、実際の勝−敗を含む配分zは同一シーズンの事後情報であり、事前予測や原因同定の検証ではない。
生成器の固定した強さ・割当機構は全seedで共通なので、seedの追加も独立した現実の標本や独立モデルの検証とは呼ばない。

## 再実行

PR #39のブランチに本変更を重ね、リポジトリの依存を導入する。保存した元experimentがある場合は最初の生成をそれで置き換えられる。
以下は再構成用の例。元experimentには較正メタデータもあるためファイルSHA自体は異なり得るが、年成績・試合ハッシュと集計値を比較できる。

```bash
mkdir -p data/synthetic/p96_discovery
PYTHONPATH=sakanalytics python - <<'PYCODE'
import json
from pathlib import Path
from synthetic_league import period_experiment
for name,seeds,conv in [('seed0',[0],1.),('holdout',[1,2],1.),('weaker_conversion',[3],.5)]:
    r=period_experiment(seeds,mean_runs=3.822333916083916,conversion=conv)
    Path(f'data/synthetic/p96_discovery/{name}.json').write_text(json.dumps(r))
PYCODE
export PYTHONPATH=sakanalytics:pythdragoras
python sakanalytics/synthetic_rule_discovery.py features --input data/synthetic/p96_discovery/seed0.json --out data/synthetic/p96_discovery/features0.json
# 探索を再現する場合だけ実行。固定候補を検証する場合は既存registryをそのまま使う。
python sakanalytics/synthetic_rule_discovery.py discover --input data/synthetic/p96_discovery/features0.json --out data/synthetic/p96_discovery/candidates-reproduced.json
# --registryには追跡済みの固定候補を指定し、別seedで再選択しない。
python sakanalytics/synthetic_rule_discovery.py features --input data/synthetic/p96_discovery/holdout.json --out data/synthetic/p96_discovery/features_holdout.json
python sakanalytics/synthetic_rule_discovery.py evaluate --input data/synthetic/p96_discovery/features_holdout.json --registry cycles/c001-chunichi/outputs/synthetic_p96_candidates.json --out data/synthetic/p96_discovery/holdout-evaluated.json
# weaker_conversion.jsonについてもfeatures→evaluateを同じregistryで実行。
```

既存propositions.tomlとsynthetic_league.pyは変更しない。探索結果の精度をPR #39の必須テストへ追加しない。
検証: 関連pytest **110 passed**。入力改ざん拒否、unknownの黙示的な陰性化拒否、混同行列と反例ID、探索へのholdout混入拒否を含む。
