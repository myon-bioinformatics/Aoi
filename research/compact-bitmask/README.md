# Compact bitmask experiment

既存の `pythdragoras/bitwise_surrogate.py` を再利用する、標準ライブラリのみの独立実験。
Layer 19/20案のうち、特徴位置の圧縮と共有ビットを破壊しない照合を先に検証する。
全20層統合・未知物体の完全復元・一意分解を実装したものではない。
子リポジトリのsubtreeや既存評価経路は変更しない。

## 実行

Aoiルートから:

```sh
python -S -m unittest discover -s research/compact-bitmask/tests -v
python -S research/compact-bitmask/benchmark.py
```

CIの既存Python 3.11〜3.15ジョブで、依存インストール前に `-S` の契約テストを実行する。
ベンチマークは3.15のみ実行し、ログに全サンプルを残す。時間の閾値は置かない。

## 使い方と保証範囲

- `FeatureLayout.from_masks(masks)` は利用中のビット位置を昇順で詰める。
  `project` と `expand` の往復は選択された特徴上で可逆。選択外のビットは失われる。
- `encode` / `decode` は固定長little-endian行ペイロード。
  位置表と版はセッション等で別途共有する。これは完成したソケットプロトコルではない。
  パディング、範囲外値、長さ違反を拒否する。
- `CompactRule` は既存ルールのスナップショット。入力の変換は任意であり、既定経路は変えない。
  NULLを含む三値フレーム処理は既存実装を利用し、本APIにNULLを渡さない。
- `match_scene` は元の観測上で各パーツの必須・禁止ビットを照合し、説明済みマスクを別管理する。
  共有幹や葉を消さない。隠蔽ビットがあれば保留する。
  全観測時は `observed` 省略可。部分観測時は明示する。
- 返るのは整合する候補群であり、親子ラベルや複数物体の割当を確定するものではない。
  シーン全体に対する禁止条件は、別物体がその特徴を持つ場合にも反応する。
  物体局所の否定条件を使うには領域・インスタンス情報が必要。
- `unexplained_mask` は未説明の証拠。共有ビットの帰属はOR観測から復元できない。
  例えば単剣0x17と盾0x7001のORは、単剣と0x7003のORとも同じ。
  共有ビットを一律に付け直す創発は行わない。学習や監査の副作用もない。

## 実測

2026-11-04、Linux x86_64・CPython 3.12.14。seed=20261104。
合成4,096行は256位置のうち8位置だけを使用する。実画像・NPB実データの結果ではない。
各時間はウォームアップ後7回の中央値。生サンプルと入力SHA-256は `measurement.json`。
既存ルール評価と集合ベース参照評価の一致はテストで確認する。

| 項目 | 元の表現 | 圧縮後 |
|---|---:|---:|
| 1行の格納幅 | 256bit | 8bit |
| 行ペイロード | 131,072 B | 4,096 B |
| 位置表込み | 131,072 B | 4,150 B |
| gzip | 8,523 B | 4,174 B（位置表込み） |
| 評価のみ | 0.796 ms | 0.558 ms（変換済み、同じ評価関数） |
| 範囲検証付き評価 | — | 1.097 ms |
| 変換＋評価 | — | 2.826 ms |

速度サンプルは機械の負荷・実行順序にも影響される小規模測定であり、一般的な高速化を示さない。
毎回の変換を含めると遅い。使用箇所は保存・転送、または特徴生成時点から密な位置を使える経路が中心となる。
8位置の行保存用レイアウトと、ルールが実際に使う4位置の推論用レイアウトは別に測定している。
位置表の54 Bは独自コンパクトJSONの試算であり、通信ヘッダ等は含まない。

追加依存0。Aoiのwheelは研究ディレクトリを含めないため、この変更によるwheel容量削減・ビルド高速化は主張しない。
他の画像・動画・テーブルアダプタへの展開には、実データにおける選択特徴の完全性と変換コストの測定が必要。

## 継続時の入口

`compact_bitmask.py` が実装、`tests/` が契約と反例、`benchmark.py` が入力生成・比較、
`measurement.json` が今回の証跡である。依存を追加せず再開できる。
次は実際の特徴生成経路で不要位置を作らない方式と比較し、位置表を共有する複数行のI/Oに適用する。
木の祖先コード、学習、C99出力、監査証明書の統合は別の変更として検証する。
